============================================================
 راهنمای آپلود فایل‌های ویرایش‌شدهٔ ملکینو (تا راند ۳۰)
============================================================

این زیپ فقط شامل فایل‌هایی است که نسبت به نسخهٔ پایه تغییر کرده‌اند
(۴۸ فایل) + همین راهنما. (شامل تغییرات راند ۳۰ و ۳۱) هیچ فایل دیگری از سایت شما حذف یا جایگزین
نمی‌شود.

------------------------------------------------------------
۱) آپلود فایل‌ها
------------------------------------------------------------
- همهٔ فایل‌های داخل زیپ را با «File Manager» هاست InfinityFree
  در پوشهٔ اصلی سایت (htdocs) آپلود کنید و جایگزین فایل‌های قبلی
  کنید.
- مهم: از آپلود وب GitHub استفاده نکنید (فایل‌های بزرگ را
  truncate می‌کند). فقط File Manager.
- ساختار پوشه‌ها را حفظ کنید (فایل‌ها همگی در ریشهٔ htdocs هستند).

------------------------------------------------------------
۲) دیتابیس — فقط در راند ۳۰ تغییر داشت (یک‌بار اجرا کنید)
------------------------------------------------------------
در راند ۳۰ ستون‌های جدید (telegram_* و phone_verified و
phone_locked در جدول users، ستون created_by_telegram_id در ads،
ستون‌های جاافتادهٔ property_requests و request_matches) و یک جدول
جدید (admin_phone_audit) اضافه شده است. دو راه دارید — هر دو
کاملاً بی‌خطر و idempotent هستند (دادهٔ موجود پاک نمی‌شود):

راه اول (ساده‌تر — پیشنهاد می‌شود):
  1. وارد پنل ادمین شوید.
  2. آدرس  melkino-migrate.php  را باز کنید.
  3. گزارش سبز را ببینید.
  4. فایل melkino-migrate.php را از هاست حذف کنید.

راه دوم:
  - فایل melkino-database.sql را در phpMyAdmin وارد (Import) کنید.
    همهٔ دستورها شرطی هستند؛ اجرای چندباره هم بی‌خطر است.

نکتهٔ مهاجرت داده: شماره‌هایی که از قبل در جدول users ثبت شده‌اند،
به‌صورت خودکار «تأییدشده + قفل‌شده» علامت‌گذاری می‌شوند تا کاربران
موجود مسدود نشوند. از این پس تغییر/حذف شماره فقط توسط ادمین
(تب کاربران پنل ادمین → دکمهٔ «حذف شماره») امکان‌پذیر است و هر
حذف در جدول admin_phone_audit لاگ می‌شود.

------------------------------------------------------------
۳) بررسی نهایی
------------------------------------------------------------
- پنل ادمین → عیب‌یاب جامع (admin-diagnostics.php) را اجرا کنید؛
  باید همهٔ بررسی‌های راند ۳۰ سبز باشند.
- پروفایل کاربری: اگر شماره ندارید، دکمهٔ «تکمیل شماره تماس» را
  تست کنید (ورود شماره → تأیید و ثبت → قفل).
- تب «کاربران» پنل ادمین: ستون «وضعیت شماره» و دکمهٔ «حذف شماره».

============================================================
 راند ۳۲ (تغییر کوچک روی همان فایل‌ها)
============================================================
- پس از «تکمیل اطلاعات حساب»، @username تلگرام دیگر در پروفایل
  نمایش داده نمی‌شود؛ فقط نام فارسیِ ثبت‌شده + شمارهٔ قفل‌شده
  دیده می‌شود. (پیش از تکمیل اطلاعات، مثل قبل @username و دکمهٔ
  راهنما نمایش داده می‌شود.)

============================================================
 فهرست تغییرات راند ۳۱ (ثبت نام فارسی + قفل نام + یکتایی شماره)
============================================================
- کاربر به‌جای نام کاربریِ تلگرام، «نام + نام خانوادگی + شمارهٔ
  موبایل» را خودش یک‌بار وارد می‌کند (مودال «تکمیل اطلاعات حساب»
  در پروفایل، با مرحلهٔ تأیید نهایی).
- نام فقط فارسی پذیرفته می‌شود (بدون عدد و حروف انگلیسی).
- پس از تأیید: نام قفل می‌شود (name_locked=1) — کاربر، فرم‌ها و
  حتی همگام‌سازی ورود تلگرام دیگر نمی‌توانند تغییرش دهند؛ فقط
  ادمین.
- اطلاعات روی همان ردیف کاربر در دیتابیس (کنار اطلاعات تلگرام)
  ذخیره می‌شود: first_name / last_name / name.
- یکتایی سراسری شماره: یک شماره فقط روی یک حساب ثبت می‌شود؛
  اکانت تلگرام دیگر نمی‌تواند همان موبایل را دوباره ثبت کند
  (پیام ۴۰۹ + کلید یکتای uniq_phone در دیتابیس).
- آگهی‌ها و درخواست‌ها از همان نام فارسیِ ثبت‌شده استفاده می‌کنند.
- کاربران قدیمی که شمارهٔ قفل‌شده دارند ولی نامشان از تلگرام است،
  در پروفایل دکمهٔ «✍️ تکمیل نام و نام خانوادگی» می‌بینند (بدون
  دست‌خوردن شماره).

⚠️ دیتابیس راند ۳۱: سه ستون جدید users (first_name/last_name/
name_locked) + کلید یکتای شماره. همان melkino-migrate.php (یا
import SQL) هر دو راند را پوشش می‌دهد — اگر شمارهٔ تکراری در
جدول users وجود داشته باشد، کلید یکتا ساخته نمی‌شود و در گزارش
هشدار می‌گیرید (اول تکراری‌ها را از تب کاربران پنل حذف کنید).

 فهرست تغییرات راند ۳۰ (خلاصه)
============================================================
- اعتبارسنجی کامل initData تلگرام/بله سمت سرور (HMAC) — گسترش
  فیلدها: language_code / is_premium / photo_url / auth_date /
  query_id / chat_type / chat_instance / start_param
- همگام‌سازی خودکار نام/یوزرنیم/عکس/زبان تلگرام در هر ورود؛
  این فیلدها برای کاربر قابل ویرایش نیستند.
- ثبت شمارهٔ تماس با مرحلهٔ تأیید نهایی («تأیید و ثبت» / «اصلاح»)
  و قفل دائم پس از تأیید — حتی درخواست دستی HTTP هم نمی‌تواند
  شماره را عوض کند (۴۰۳).
- هر ۶ فرم ثبت ملک + فرم درخواست: نام/شماره/telegram_id/user_id
  فقط از حساب تأییدشدهٔ سمت سرور؛ بدون شمارهٔ تأییدشده، ثبت
  مسدود است + راهنمای «تکمیل شماره تماس».
- رکورد آگهی: owner_user_id + created_by_telegram_id ثبت می‌شود.
- ورود با کد یک‌بارمصرف پیامک → شماره تأییدشده+قفل‌شده.
- رفع شکاف قدیمی اسکیمای property_requests / request_matches
  (در نصب تازه، ثبت درخواست خطا می‌گرفت).
